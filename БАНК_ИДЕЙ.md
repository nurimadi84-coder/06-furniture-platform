## 1. Суть продукта

**Проблема.** Клиент хочет индивидуальную мебель, но боится «чёрного ящика»: непонятна цена, долгий ответ менеджера, нет прозрачности производства.

**Решение.** Лёгкий веб-MVP, который за минуту даёт **вилку цены**, принимает **заявку**, умеет **прочитать эскиз** и показывает **статус заказа** из цеха.

| Для кого | Ценность |
|---|---|
| Клиент | Мгновенная ориентировочная стоимость, заявка в 1 клик, трекинг |
| Менеджер | Лиды в БД + Telegram, меньше ручных «посчитайте примерно» |
| Производство | Публичный этап заказа без звонков «ну как там?» |

**Бренд:** MebelExpress  
**Рынок MVP:** Казахстан (телефон `+77…` / `87…`, валюта **KZT**)

## 2. Семь опорных идей

Идеи, вокруг которых собран текущий MVP:

| # | Идея | Как реализовано |
|---:|---|---|
| 1 | **Мгновенная цена** | Детерминированный `PricingEngine`, вилка ±5…15% |
| 2 | **Квиз вместо формы** | 4 шага: тип → габариты → материалы → цена + заявка |
| 3 | **Эскиз → автозаполнение** | Vision API или безопасный heuristic-fallback |
| 4 | **Лид без трения** | Имя + KZ-телефон, запись в SQLite, пуш в Telegram |
| 5 | **Прозрачный цех** | Публичный трекинг по короткому коду заказа |
| 6 | **Лёгкий фронт** | Без React/Vue: HTML + Tailwind CDN + Vanilla JS |
| 7 | **Один клик в Docker** | FastAPI + Nginx статика, `docker compose up` |

## 3. Пользовательские сценарии

### A. Быстрый расчёт и заявка

```text
Hero → «Рассчитать»
  → выбор типа (шкаф / кухня / кровать)
  → слайдеры Ш×В×Г
  → материал + фурнитура + опции
  → вилка цены на экране
  → имя + телефон → лид в БД (+ Telegram)
```

### B. С эскиза

```text
Drag & Drop фото/чертежа
  → «Распознать и посчитать»
  → автозаполнение калькулятора
  → проверка размеров → заявка
```

### C. «Где мой заказ?»

```text
track.html → ввод номера (демо: TEST1234)
  → progress-bar: Замер → Раскрой → Сборка → Монтаж → Готово
  → фото последнего этапа из цеха
```

## 5. Калькулятор и ценообразование

### Формула

\[
Cost = (W \times H \times D \times MaterialFactor) + Hardware + Assembly + Extras
\]

\[
Price_{min} = Cost \times 0.95,\quad Price_{max} = Cost \times 1.15
\]

Размеры вводятся в **мм**, внутри движка переводятся в **м³**. Валюта: **KZT**.

### Справочники MVP

| Параметр | Значения | Влияние |
|---|---|---|
| Тип | шкаф · кухня · кровать | множитель 1.0 / 1.35 / 0.85 |
| Материал | эконом · стандарт · премиум | 85k / 120k / 180k ₸ за м³ |
| Фурнитура | базовая · Blum · DTC | 25k / 75k / 55k ₸ |
| Сборка | по типу | 40k / 90k / 30k ₸ |
| Опции | подсветка · ящики · зеркала | 18k / 35k / 22k ₸ |

### Ограничения габаритов

| Ось | Min | Max |
|---|---:|---:|
| Ширина | 300 | 6000 |
| Высота | 300 | 3500 |
| Глубина / длина | 200 | 2500 |

> Верхняя граница глубины **2500** нужна, чтобы кровать (длина ~2000) проходила через Vision → калькулятор без ошибки.

### Пример (проверено на API)

Шкаф 1800×2400×600, стандарт, Blum, подсветка:

| Статья | Сумма, ₸ |
|---|---:|
| Материал | 311 040 |
| Фурнитура | 75 000 |
| Сборка | 40 000 |
| Опции | 18 000 |
| **База** | **444 040** |
| Вилка | **421 838 – 510 646** |

## 6. Данные и статусы

### Lead (заявка)

| Поле | Смысл |
|---|---|
| `client_name`, `phone` | Контакт (KZ-формат) |
| `furniture_type` | Выбранный тип |
| `estimated_price_min/max` | Вилка с калькулятора |
| `status` | `new` → `contacted` → `measuring` → `closed` |

### Order (производство)

| Поле | Смысл |
|---|---|
| `order_number` | Короткий публичный код |
| `current_stage` | Текущий этап цеха |
| `stage_photo_url` | Фото последнего этапа |

**Этапы:** `measuring` → `cutting` → `assembly` → `delivery` → `completed`  
**Демо:** `TEST1234` (стадия `assembly`)

> В SQLite хранятся **values** enum (`assembly`, `new`), не имена (`ASSEMBLY`, `NEW`).

```text
├── frontend/
│   ├── index.html              # лендинг + квиз + AI-upload
│   ├── track.html              # статус заказа
│   ├── js/                     # calculator, vision_upload, tracking
│   └── css/styles.css
├── nginx/nginx.conf
├── docker-compose.yml
├── README.md                   # быстрый старт
└── БАНК_ИДЕЙ.md                # этот файл
```

**Принципы кода**

- Strict typing + `async` для I/O  
- CORS для локального фронта  
- Без тяжёлых SPA-фреймворков на MVP  
- Toast-ошибки на формах  
- Graceful degrade: нет Telegram / OpenAI → продукт всё равно работает

## 8. API-карта

| Метод | Путь | Идея |
|---|---|---|
| `POST` | `/api/v1/calculator/calculate` | Мгновенная вилка + breakdown |
| `POST` | `/api/v1/leads/create` | Заявка + фоновый Telegram |
| `POST` | `/api/v1/vision/estimate-sketch` | Эскиз → параметры (multipart) |
| `GET` | `/api/v1/tracking/{order_number}` | Публичный статус |
| `GET` | `/health` | Liveness |
| `GET` | `/docs` | Swagger |

**Телефон:** `+77XXXXXXXXX` или `87XXXXXXXXX` (нормализуется в `+7…`).  
**Vision без ключа:** heuristic `200` + понятный `notes`, не `500`.  
**Не-изображение:** `400` (проверка magic bytes).

## 10. Интеграции

| Сервис | Зачем | Без ключа |
|---|---|---|
| **Telegram Bot API** | Алерт о новой заявке менеджеру | Лид всё равно в SQLite |
| **OpenAI GPT-4o Vision** | Разбор эскиза/фото | Типовые размеры + пометка heuristic |
| **Nginx** | Статика + proxy `/api/` | Локально: Live Server / `http.server` |

Переменные: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `OPENAI_API_KEY`, `DATABASE_URL`, `CORS_ORIGINS`.

## 11. Запуск и приёмка

### Локально

```bash
# API
cd 06-furniture-platform/backend
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000

# UI
cd 06-furniture-platform/frontend
python -m http.server 5500
```

### Docker

```bash
cd 06-furniture-platform
docker compose up --build
# → http://localhost:8080
```
